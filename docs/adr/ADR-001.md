# ADR-001 — Application architecture (accepted as engineering baseline)
Date: 2026-10-18. Production approval: **not granted**.

Decision: TypeScript modular monolith, NestJS + Fastify API, React + Vite separate experiences, PostgreSQL + PostGIS authoritative database, pnpm workspace; local-only browser persistence for approved offline barangay workflows; portable Docker deployment with cloud first and possible LGU-hosted components later.

## Responsibilities
API owns security and transactional state changes. Database is the only authoritative write master. Offline client entries are drafts until acknowledged. Public endpoints expose only approved aggregate disclosures. No unauthorized cross-barangay access.

## Sync protocol target (NOT implemented)
Push operation UUID + actor/device/tenant scope + entity/version + minimal payload. Validate identity/scope, idempotency, base revision, domain invariants in one transaction; acknowledge with authoritative revision or typed conflict. Pull via scoped opaque cursor. No last-write-wins for household membership, disaster impact, approvals, or inventory.

## Auth target (NOT implemented)
Named accounts, Argon2id, secure HTTP-only cookies, CSRF protection, server-side sessions, MFA for privileged users, deny-by-default RBAC plus resource scoping and audit. No live personal data until proven operational.

## Consequences and trade-offs
Modular monolith simplifies transactions and deployment but needs boundary discipline. PWA speeds rollout but browser local storage can be evicted or stolen; require device controls and minimization. PostGIS provides spatial analytics but requires reviewed SQL and validated coordinate data. Cloud-first pilot eases iteration; hybrid production requires an RTO/RPO agreement, backup testing and failover drills.
